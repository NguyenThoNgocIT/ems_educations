## NHÓM 1 — LOOKUP / SUPPORT APIs (dùng để populate form trước khi tạo request)

─────────────────────────────────────────────────────────────────
API-01 GET /api/v1/instructors/me/course-classes
Lấy danh sách lớp học phần GV đang phụ trách trong kỳ
─────────────────────────────────────────────────────────────────
AUTH : ROLE_INSTRUCTOR
QUERY : semesterId (UUID, required)

LOGIC:

1. Lấy InstructorId từ SecurityContext (JWT sub → UserId → EmployeeId → InstructorId)
2. JOIN TeachingAssignments ta → CourseClasses cc → Courses c → Semesters sem
3. Filter: ta.InstructorId = :instructorId AND ta.SemesterId = :semesterId
   AND ta.IsActive=1 AND ta.DeletedAt IS NULL
4. Với mỗi lớp → tính fixedDays từ Schedules WHERE ScheduleType='FIXED'
   GROUP BY DayOfWeek → "T2, T3, T6 | Tiết 1–3"

RESPONSE 200:
List<CourseClassSummaryDTO> {
courseClassId : UUID
classCode : String // "IT301.001"
courseName : String // "OOP"
credits : Integer
totalPeriods : Integer // credits \* 15
taughtPeriods : Integer // SUM(NumberOfPeriods) WHERE ScheduleStatus='COMPLETED'
remainingPeriods : Integer
fixedSchedule : String // "T2, T3, T6 | Tiết 1–3 | P.A201"
currentStudents : Integer
semesterName : String
}

VALIDATE:
□ semesterId tồn tại và IsActive=1
□ GV có ít nhất 1 TeachingAssignment trong kỳ → else 404

─────────────────────────────────────────────────────────────────
API-02 GET /api/v1/schedules/fixed-sessions
Lấy danh sách buổi lịch cố định của 1 lớp (để GV chọn buổi nghỉ)
─────────────────────────────────────────────────────────────────
AUTH : ROLE_INSTRUCTOR
QUERY : courseClassId (UUID, required)
fromDate, toDate (optional, default = today → endOfSemester)

LOGIC:

1. Verify GV đang phụ trách courseClassId
2. SELECT \* FROM Schedules
   WHERE CourseClassId = :ccId
   AND ScheduleType = 'FIXED'
   AND Date >= :fromDate AND Date <= :toDate
   AND IsActive = 1 AND DeletedAt IS NULL
   ORDER BY Date
3. Map từng record → ScheduleSessionDTO

RESPONSE 200:
List<ScheduleSessionDTO> {
scheduleId : UUID
date : LocalDate // "2024-12-16"
dayOfWeek : String // "T2"
timeSlotCode : String // "Tiết 1–3"
timeSlotStart : String // "07:00"
timeSlotEnd : String // "09:30"
numberOfPeriods : Integer
roomCode : String // "A201"
scheduleStatus : String // PLANNED | COMPLETED | ABSENT | CANCELLED
hasAdjustment : Boolean // đã có request chưa
}

VALIDATE:
□ courseClassId tồn tại
□ GV phụ trách lớp này (TeachingAssignments)
□ Không trả về buổi đã CANCELLED / đã qua mà chưa dạy bù

─────────────────────────────────────────────────────────────────
API-03 GET /api/v1/rooms/available
Lấy danh sách phòng trống theo ngày + khung tiết + sức chứa tối thiểu
─────────────────────────────────────────────────────────────────
AUTH : ROLE_INSTRUCTOR, ROLE_ADMIN
QUERY : date (LocalDate, required)
timeSlotId (UUID, required)
minCapacity (Integer, optional, default=0)
buildingId (UUID, optional)

LOGIC:

1. Lấy tất cả phòng active: Rooms WHERE IsActive=1 AND Capacity >= minCapacity
2. Trừ đi phòng đã bị đặt:
   SELECT DISTINCT RoomId FROM Schedules
   WHERE Date = :date AND TimeSlotId = :timeSlotId
   AND ScheduleStatus NOT IN ('CANCELLED')
   AND IsActive=1 AND DeletedAt IS NULL
   UNION
   SELECT DISTINCT ProposedRoomId FROM ScheduleAdjustmentRequests
   WHERE ProposedDate = :date AND ProposedTimeSlotId = :timeSlotId
   AND Status IN ('PENDING','APPROVED')
3. Kết quả = tất cả phòng − phòng bận

RESPONSE 200:
List<RoomAvailableDTO> {
roomId : UUID
roomCode : String // "A201"
roomName : String
capacity : Integer
buildingName : String
floorNumber : Integer
hasProjector : Boolean
hasAirConditioner: Boolean
hasComputer : Boolean
status : String // "AVAILABLE"
}

VALIDATE:
□ date không phải ngày trong quá khứ (> today - 1)
□ timeSlotId tồn tại và IsActive=1
□ date nằm trong Semester hiện tại

## NHÓM 2 — VALIDATE TRƯỚC KHI TẠO REQUEST (live check khi GV nhập form)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

─────────────────────────────────────────────────────────────────
API-05 POST /api/v1/schedule-adjustments/validate
Validate toàn bộ thông tin trước khi GV submit (không tạo record)
─────────────────────────────────────────────────────────────────
AUTH : ROLE_INSTRUCTOR
REQUEST BODY:
{
"courseClassId" : "UUID",
"requestType" : "ABSENT_MAKEUP | EXTRA_SESSION | RESCHEDULE | ROOM_CHANGE",
"absentDate" : "2024-12-16", // ngày nghỉ / ngày cần điều chỉnh
"absentTimeSlotId" : "UUID", // khung tiết nghỉ
"absentPeriods" : 3,
"proposedDate" : "2024-12-19", // ngày bù đề xuất (nullable nếu EXTRA)
"proposedTimeSlotId": "UUID",
"proposedRoomId" : "UUID",
"proposedPeriods" : 3
}

LOGIC — Chạy tuần tự 8 rules, collect ALL errors + warnings:

[R1] absentDate có lịch FIXED của lớp không?
→ SELECT COUNT(\*) FROM Schedules
WHERE CourseClassId=:ccId AND Date=:absentDate
AND ScheduleType='FIXED' AND ScheduleStatus NOT IN ('CANCELLED','ABSENT')
→ = 0 → ERROR "Ngày {absentDate} không có lịch dạy cố định"

[R2] Buổi này đã có request PENDING/APPROVED chưa?
→ SELECT COUNT(\*) FROM ScheduleAdjustmentRequests
WHERE OriginalScheduleId = (ScheduleId từ R1)
AND Status IN ('PENDING','APPROVED')
→ > 0 → ERROR "Buổi này đã có yêu cầu điều chỉnh đang xử lý"

[R3] (Nếu có proposedDate) GV bị trùng lịch ngày bù?
→ SELECT s.ScheduleId, s.CourseClassId FROM Schedules s
JOIN TeachingAssignments ta ON ta.CourseClassId = s.CourseClassId
WHERE ta.InstructorId = :instructorId
AND s.Date = :proposedDate AND s.TimeSlotId = :proposedTimeSlotId
AND s.ScheduleStatus NOT IN ('CANCELLED')
AND s.CourseClassId <> :courseClassId
→ exists → ERROR "GV đã có lịch dạy lớp {classCode} vào {proposedDate} {timeSlot}"

[R4] (Nếu có proposedDate) GV có đơn nghỉ APPROVED trong ngày bù?
→ SELECT \* FROM EmployeeLeaveRequests elr
JOIN Instructors i ON i.EmployeeId = elr.EmployeeId
WHERE i.InstructorId = :instructorId
AND :proposedDate BETWEEN elr.FromDate AND elr.ToDate
AND elr.Status = 2
→ exists → ERROR "GV có đơn nghỉ phép được duyệt ngày {proposedDate}: {reason}"

[R5] (Nếu có proposedRoomId) Phòng có bị trùng?
→ SELECT COUNT(\*) FROM Schedules
WHERE RoomId = :proposedRoomId AND Date = :proposedDate
AND TimeSlotId = :proposedTimeSlotId
AND ScheduleStatus NOT IN ('CANCELLED')
→ > 0 → ERROR "Phòng {roomCode} đã có lớp khác vào {proposedDate} {timeSlot}"
→ Kèm gợi ý: List<RoomAvailableDTO> (gọi logic API-03)

[R6] proposedDate nằm trong học kỳ không?
→ Lấy Semester từ CourseClass → check StartDate ≤ proposedDate ≤ EndDate
→ false → ERROR "Ngày bù {proposedDate} nằm ngoài học kỳ"

[R7] proposedDate có phải ngày lễ không?
→ Check HolidayDates (hoặc Settings nếu chưa có bảng riêng)
→ exists → ERROR "Ngày {proposedDate} là ngày nghỉ lễ: {holidayName}"

[R8] (WARN) SV của lớp có lịch môn khác vào ngày bù không?
→ SELECT DISTINCT cr.StudentId FROM CourseRegistrations cr
JOIN Schedules s ON s.CourseClassId = cr.CourseClassId
WHERE cr.CourseClassId <> :courseClassId
AND s.Date = :proposedDate AND s.TimeSlotId = :proposedTimeSlotId
AND cr.StudentId IN (SELECT StudentId FROM CourseRegistrations
WHERE CourseClassId = :courseClassId)
→ count > 0 → WARN "{count} SV có thể bị trùng lịch môn khác"

[R9] (WARN) proposedDate cách ngày thi < 7 ngày?
→ Lấy ExamDate từ Exams JOIN CourseClasses
→ WARN "Ngày bù cách kỳ thi chỉ {days} ngày, nên thông báo sớm cho SV"

RESPONSE 200:
{
"valid" : true/false,
"results" : [
{ "rule": "R1", "status": "OK", "message": "Thứ 2 — đúng ngày lịch cố định" },
{ "rule": "R3", "status": "ERROR", "message": "GV đã có lịch lớp CS201 tiết 7–9" },
{ "rule": "R5", "status": "ERROR", "message": "Phòng B302 trùng",
"suggestions": [{ "roomId":"...", "roomCode":"A101", "capacity":40 }] },
{ "rule": "R8", "status": "WARN", "message": "3 SV có thể trùng lịch môn MATH" },
{ "rule": "R9", "status": "WARN", "message": "Ngày bù cách thi 5 ngày" }
]
"proposedSlots" : [ // trạng thái từng khung tiết của ngày đề xuất
{ "timeSlotId":"...", "slotCode":"SLOT_1_3", "label":"Tiết 1–3",
"periods":3, "startTime":"07:00", "endTime":"09:30",
"status":"AVAILABLE" },
{ "timeSlotId":"...", "slotCode":"SLOT_4_6", "label":"Tiết 4–6",
"periods":3, "status":"AVAILABLE" },
{ "timeSlotId":"...", "slotCode":"SLOT_7_9", "label":"Tiết 7–9",
"periods":3, "status":"AVAILABLE" },
{ "timeSlotId":"...", "slotCode":"SLOT_10_12","label":"Tiết 10–12",
"periods":3, "status":"GV_CONFLICT", // ← chip ⚠
"conflictReason":"GV đang dạy lớp CS201.002" }
],

"proposedRooms" : [ // danh sách phòng + trạng thái cho ngày+tiết đã chọn
{ "roomId":"...", "roomCode":"A201", "capacity":45, "status":"AVAILABLE" },
{ "roomId":"...", "roomCode":"A101", "capacity":40, "status":"AVAILABLE" },
{ "roomId":"...", "roomCode":"B302", "capacity":50, "status":"ROOM_CONFLICT",
"conflictReason":"Lớp CS201.002 đang dùng tiết 7–9" },
{ "roomId":"...", "roomCode":"C203", "capacity":35, "status":"AVAILABLE" }
]
}
Status enum cho slot:

AVAILABLE— xanh, chọn được
GV_CONFLICT— đỏ ⚠, GV bận
LEAVE_CONFLICT— đỏ ⚠, GV có đơn nghỉ
STUDENT_CONFLICT— vàng ⚠, SV trùng (soft warn)

Status enum cho room:

AVAILABLE— xanh
ROOM_CONFLICT— đỏ ⚠, phòng bị đặt
INSUFFICIENT_CAPACITY— vàng ⚠, không đủ chỗ
VALIDATE INPUT:
□ courseClassId, requestType, absentDate, absentTimeSlotId, absentPeriods: required
□ requestType IN ['ABSENT_MAKEUP','EXTRA_SESSION','RESCHEDULE','ROOM_CHANGE']
□ absentPeriods: 1–10 (không âm, không quá tổng tiết học phần)
□ proposedDate required nếu requestType IN ['ABSENT_MAKEUP','RESCHEDULE']
□ proposedPeriods = absentPeriods nếu ABSENT_MAKEUP (bù đủ số tiết)
□ proposedDate >= today (không bù ngày quá khứ)

API-06 POST /api/v1/schedule-adjustments
GV tạo yêu cầu điều chỉnh lịch
─────────────────────────────────────────────────────────────────
AUTH : ROLE_INSTRUCTOR
REQUEST BODY (multipart/form-data):
data: {
"courseClassId" : "UUID",
"requestType" : "ABSENT_MAKEUP",
"absentDate" : "2024-12-16",
"absentTimeSlotId" : "UUID",
"absentPeriods" : 3,
"reason" : "Tham gia hội thảo khoa học tại Hà Nội",
"proposedDate" : "2024-12-19",
"proposedTimeSlotId": "UUID",
"proposedRoomId" : "UUID",
"proposedPeriods" : 3,
"note" : "SV đã được thông báo trước"
}
attachment: File (optional, PDF/JPG/PNG ≤ 5MB)

LOGIC (@Transactional):

1. Gọi lại toàn bộ validate logic của API-05
   → Nếu có bất kỳ ERROR → throw AdjustmentValidationException(results)
   → Nếu chỉ WARN → cho phép tiếp tục, lưu warnings vào record
2. Upload file đính kèm → lưu vào storage → lấy URL
3. Tìm OriginalScheduleId:
   SELECT ScheduleId FROM Schedules
   WHERE CourseClassId=:ccId AND Date=:absentDate
   AND TimeSlotId=:absentTimeSlotId AND ScheduleType='FIXED'
4. INSERT ScheduleAdjustmentRequests:
   {
   InstructorId, OriginalScheduleId, CourseClassId,
   RequestType, AbsentDate, AbsentPeriods,
   Reason, AttachmentUrl,
   ProposedDate, ProposedTimeSlotId, ProposedRoomId, ProposedPeriods,
   Note, Warnings (JSON array of warn messages),
   Status = 'PENDING',
   CreatedBy = currentUserId
   }
5. Gửi thông báo admin:
   INSERT Notifications (Type='SCHEDULE_ADJUSTMENT_REQUEST', RefId=requestId, ...)
   INSERT UserNotifications cho từng UserId có ROLE_ADMIN / ROLE_SCHEDULE_MANAGER
6. Return requestId + status

RESPONSE 201:
{
"requestId" : "UUID",
"status" : "PENDING",
"message" : "Yêu cầu đã gửi. Admin sẽ xem xét trong 24h.",
"warnings" : ["3 SV có thể trùng lịch môn MATH"]
}

VALIDATE INPUT (ngoài logic R1–R9):
□ reason: 10–500 ký tự, not blank
□ attachment nếu có: ≤ 5MB, type IN [pdf, jpg, jpeg, png]
□ GV chỉ được tạo request cho lớp mình phụ trách
□ Không tạo trùng: cùng courseClassId + absentDate + Status IN [PENDING,APPROVED]
→ ERROR "Đã tồn tại yêu cầu cho buổi này"

## NHÓM 4 — ADMIN WORKFLOW

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

API-11 GET /api/v1/admin/schedule-adjustments
Admin xem tất cả yêu cầu (có filter)
─────────────────────────────────────────────────────────────────
AUTH : ROLE_ADMIN | ROLE_SCHEDULE_MANAGER
QUERY : semesterId, status, instructorId, requestType,
courseClassId, fromDate, toDate,
page (0), size (20), sort (createdAt desc)

LOGIC:
Dynamic query (Specification hoặc JPQL với optional params)
JOIN thêm: conflictSummary (số conflict), instructorName, departmentName

RESPONSE 200: Page<AdminAdjustmentSummaryDTO> {
...tất cả fields của GV +
"instructorName" : "Nguyễn Văn An",
"departmentName" : "CNTT",
"conflictCount" : 2,
"conflictDetails" : [
{ "rule":"R5", "message":"Phòng B302 trùng", "suggestions":[...] }
],
"isAutoApprovalEligible": true // không có conflict nào
}

─────────────────────────────────────────────────────────────────
API-12 POST /api/v1/admin/schedule-adjustments/{requestId}/approve
Admin duyệt yêu cầu → trigger cập nhật lịch
─────────────────────────────────────────────────────────────────
AUTH : ROLE_ADMIN | ROLE_SCHEDULE_MANAGER
REQUEST BODY:
{ "note": "Đã xác nhận phòng A201 trống. Duyệt." }

LOGIC (@Transactional — QUAN TRỌNG: phải atomic):

1. Pessimistic lock record: SELECT ... FOR UPDATE
2. Re-validate R3, R4, R5 tại thời điểm duyệt (phòng có thể vừa bị đặt)
   → Nếu có conflict mới → throw ConflictException → Status = CONFLICT_DETECTED
3. UPDATE ScheduleAdjustmentRequests:
   { Status='APPROVED', ReviewedBy=adminId, ReviewedAt=NOW(), AdminNote=note }
4. UPDATE Schedules (buổi gốc):
   SET ScheduleStatus = 'ABSENT',
   Note = 'Nghỉ — đã bù ngày {proposedDate}',
   UpdatedAt = NOW(), UpdatedBy = adminId
5. INSERT Schedules (buổi bù):
   {
   CourseClassId, EmployeeId (= instructor's EmployeeId),
   SemesterId, RoomId = proposedRoomId,
   DayOfWeek = dayOfWeek(proposedDate),
   Date = proposedDate,
   TimeSlotId = proposedTimeSlotId,
   NumberOfPeriods = proposedPeriods,
   ScheduleType = 'MAKEUP',
   MakeupForScheduleId = originalScheduleId, -- FK mới
   ScheduleStatus = 'PLANNED',
   Note = 'Dạy bù cho buổi {absentDate}',
   CreatedBy = adminId
   }

API-16 GET /api/v1/schedules/calendar
Lấy lịch dạy của GV theo tháng (render mini calendar)
─────────────────────────────────────────────────────────────────
AUTH : ROLE_INSTRUCTOR | ROLE_ADMIN
QUERY : instructorId (UUID), month (1–12), year (2024)

LOGIC:
SELECT s.Date, s.ScheduleType, s.ScheduleStatus,
s.NumberOfPeriods, ts.SlotCode, r.Code AS RoomCode,
cc.ClassCode, c.Name AS CourseName
FROM Schedules s
JOIN TeachingAssignments ta ON ta.CourseClassId = s.CourseClassId
JOIN TimeSlots ts ON ts.TimeSlotId = s.TimeSlotId
JOIN Rooms r ON r.RoomId = s.RoomId
JOIN CourseClasses cc ON cc.CourseClassId = s.CourseClassId
JOIN Courses c ON c.CourseId = cc.CourseId
WHERE ta.InstructorId = :instructorId
AND MONTH(s.Date) = :month AND YEAR(s.Date) = :year
AND s.IsActive = 1 AND s.DeletedAt IS NULL
ORDER BY s.Date, ts.StartTime

RESPONSE 200:
{
"month": 12, "year": 2024,
"days": {
"2024-12-02": [{ "type":"FIXED", "status":"COMPLETED", "class":"IT301.001", ... }],
"2024-12-16": [{ "type":"FIXED", "status":"ABSENT", "class":"IT301.001", ... }],
"2024-12-19": [{ "type":"MAKEUP", "status":"PLANNED", "class":"IT301.001", ... }]
}
}

─────────────────────────────────────────────────────────────────
API-17 GET /api/v1/schedules/teaching-progress
Báo cáo tiến độ giảng dạy (bảng 8 cột)
─────────────────────────────────────────────────────────────────
AUTH : ROLE_INSTRUCTOR | ROLE_ADMIN
QUERY : semesterId (UUID, required)
instructorId (UUID, optional — admin xem GV khác)
courseClassId (UUID, optional)

LOGIC:
WITH progress AS (
SELECT
cc.CourseClassId, cc.ClassCode,
c.Name AS CourseName, c.Credits,
COALESCE(cc.StartDate, sem.StartDate) AS StartDate,
COALESCE(cc.EndDate, sem.EndDate) AS EndDate,
CASE WHEN c.TheoryHours IS NOT NULL
THEN c.TheoryHours + COALESCE(c.PracticeHours,0)
WHEN c.CourseType='PRACTICE' THEN c.Credits*30
WHEN c.CourseType='INTERN' THEN c.Credits*45
ELSE c.Credits*15 END AS TotalPeriods,
SUM(CASE WHEN s.ScheduleStatus='COMPLETED'
THEN COALESCE(s.NumberOfPeriods,1) ELSE 0 END) AS TaughtPeriods,
COUNT(CASE WHEN s.ScheduleStatus='ABSENT' THEN 1 END) AS AbsentSessions,
COUNT(CASE WHEN s.ScheduleStatus='PLANNED'
AND s.Date <= GETDATE() THEN 1 END) AS MissedPlanned
FROM CourseClasses cc
JOIN Courses c ON c.CourseId = cc.CourseId
JOIN Semesters sem ON sem.SemesterId = cc.SemesterId
JOIN TeachingAssignments ta ON ta.CourseClassId = cc.CourseClassId
LEFT JOIN Schedules s ON s.CourseClassId = cc.CourseClassId AND s.IsActive=1
WHERE ta.InstructorId = :instructorId
AND cc.SemesterId = :semesterId
GROUP BY cc.CourseClassId, cc.ClassCode, c.Name, c.Credits,
cc.StartDate, cc.EndDate, sem.StartDate, sem.EndDate,
c.TheoryHours, c.PracticeHours, c.CourseType
)
SELECT *, TotalPeriods - TaughtPeriods AS RemainingPeriods,
CAST(TaughtPeriods \* 100.0 / NULLIF(TotalPeriods,0) AS DECIMAL(5,1)) AS ProgressPct
FROM progress

RESPONSE 200: List<TeachingProgressDTO>
{
"classCode" : "IT301.001",
"courseName" : "OOP — 2TC",
"startDate" : "2024-09-02",
"endDate" : "2024-12-31",
"totalPeriods" : 30,
"taughtPeriods" : 18,
"absentSessions" : 2,
"remainingPeriods": 12,
"progressPct" : 60.0,
"alert" : "BEHIND_SCHEDULE" // null | ON_TRACK | BEHIND_SCHEDULE | CRITICAL
}

ALERT logic:
progressPct >= expected (tính theo ngày đã qua / tổng ngày học kỳ) → ON_TRACK
< expected - 10% → BEHIND_SCHEDULE
< expected - 20% → CRITICAL (hoặc < 7 ngày cuối kỳ mà còn > 20% tiết)

## BẢNG TỔNG HỢP VALIDATE — TẤT CẢ TRƯỜNG HỢP LỖI

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

LAYER 1 — Input validation (DTO @Valid)
✗ courseClassId null / invalid UUID format
✗ requestType không thuộc enum
✗ absentDate null | định dạng sai | là ngày quá khứ > 0 ngày
✗ absentPeriods < 1 hoặc > 10
✗ proposedDate null khi requestType = ABSENT_MAKEUP | RESCHEDULE
✗ proposedDate < today
✗ proposedPeriods != absentPeriods khi ABSENT_MAKEUP
✗ reason blank | < 10 ký tự | > 500 ký tự
✗ attachment > 5MB | type không hợp lệ

LAYER 2 — Business validation (Service)
✗ GV không phụ trách lớp này
✗ absentDate không có lịch FIXED
✗ Đã có request PENDING/APPROVED cho buổi đó
✗ GV trùng lịch dạy ngày bù
✗ GV có đơn nghỉ APPROVED ngày bù
✗ Phòng đề xuất bị trùng
✗ proposedDate ngoài học kỳ
✗ proposedDate là ngày lễ

LAYER 3 — Concurrency (tại thời điểm APPROVE)
✗ Phòng vừa bị đặt bởi request khác (TOCTOU)
✗ GV vừa được assign lớp mới vào khung giờ bù
✗ Request vừa bị GV hủy (Status đã thay đổi)
→ Giải quyết: Pessimistic lock + re-validate tại thời điểm approve

LAYER 4 — Authorization
✗ GV xem/sửa request của GV khác → 403
✗ SV gọi admin API → 403
✗ Token hết hạn → 401
✗ GV submit request khi account bị suspended → 403

LAYER 5 — State machine (Status transitions)
Chỉ cho phép các chuyển trạng thái hợp lệ:
PENDING → APPROVED | REJECTED | RETURNED | CONFLICT_DETECTED
RETURNED → PENDING (khi GV chỉnh sửa lại)
CONFLICT_DETECTED → APPROVED | REJECTED
APPROVED → [không thể thay đổi]
REJECTED → [không thể thay đổi]
Mọi transition khác → ERROR "Không thể thực hiện hành động này ở trạng thái hiện tại"

## RESPONSE FORMAT CHUẨN

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SUCCESS:
{ "code": 200, "message": "Success", "data": { ... } }

ERROR:
{
"code" : 400,
"message" : "Validation failed",
"errors" : [
{ "field": "proposedDate", "message": "Ngày bù nằm ngoài học kỳ" },
{ "field": "proposedRoomId", "message": "Phòng A201 đã được đặt" }
]
}

CONFLICT (validate API-05):
{
"code" : 200,
"valid" : false,
"results": [
{ "rule":"R3", "status":"ERROR", "message":"...", "suggestions":[...] },
{ "rule":"R8", "status":"WARN", "message":"..." }
]
}

3 điểm kỹ thuật quan trọng nhất

1. API-05 (validate) phải tách riêng khỏi API-06 (submit)
   Cho phép live-check ngay khi GV nhập form mà không tạo record — UX sạch, không rác data.
2. API-12 (approve) phải re-validate R3,R4,R5 tại thời điểm duyệt
   Đây là TOCTOU race condition — phòng có thể vừa bị đặt trong lúc admin đang xem xét. Dùng SELECT ... FOR UPDATE(pessimistic lock) trên record request.
3. State machine nghiêm ngặt
   PENDING → APPROVED / REJECTED / RETURNED / CONFLICT_DETECTED
   RETURNED → PENDING (GV sửa lại)
   APPROVED / REJECTED → [terminal, không đổi được]
   Mọi transition không hợp lệ → 400 ngay tại Service layer, không để xuống DB.

Điểm quan trọng nhất: ScheduleAdjustmentRequestsđang PENDING cũng phải được tính vào "phòng bận" — tránh 2 GV cùng đặt phòng A201 cùng ngày giờ, cả 2 đều pass validate rồi admin approve cả 2.
